# PBI Layout Grid — 产品需求文档（草稿 v0.3）

## 1. 一句话
单文件网页工具：**输入**一份"组件+坐标"列表，用户在 16:9 画布上拖拽调整位置，**输出**修改后的列表。核心是拖拽体验要明显好于在 Power BI 里调。

## 2. 背景与痛点
- 在 Power BI 里精确摆放视觉：逐个点选、手输坐标、看不到整页全貌、没有好用的吸附。
- 作者对布局要求严格，调一次布局需 **2–3 小时**（基线）。
- 开发阶段为 PBIP（新格式 PBIR），AI 直接修改 JSON，缺的是"人直观确定目标位置并交给 AI"的一环。

## 3. 用户
内部 BI 团队约 2 人；后续可能开源。

## 4. 成功标准
- 基线：一次布局 2–3 小时。目标：**≤ 30 分钟**。
- 定性：拖动手感比 Power BI 好；自动吸附让对齐不费力；改坐标步骤比 Power BI 更少。

## 5. 职责边界
| 环节 | 谁负责 |
|------|--------|
| 从 PBIP 的 visual.json 提取组件坐标列表 | **不在本工具内**（由 AI/脚本完成） |
| 导入列表、拖拽调整、导出新列表 | **本工具** |
| 把新列表写回 visual.json | **不在本工具内**（由 AI 完成） |

## 6. 输入 / 输出格式
**暂留空**，由作者后续整理。原则：输入与输出**结构保持一致**，且**尽可能简单**（回灌 AI 无需转换）。

## 7. 交互设计原则
- **吸附：** 背景网格 10px；拖动默认吸附到 10px 网格；靠近其他组件的边/中心（阈值 10px）自动贴齐并出引导线。
- **可关闭吸附：** 按住修饰键临时关闭，另有开关常驻关闭，保证可到 1px 精度。
- **输入坐标：** 选中组件后 X / Y / 宽 / 高四个输入框**始终可见**，无需点开面板；Tab 切换、Enter 应用，输入框内上下键加减。目标：比 Power BI 少 N 步（Power BI：选组件 → 打开格式面板 → 展开常规 → 展开属性 → 输入）。
- **键盘：** 方向键 1px 微调（Shift 为 10px）。
- **撤销/重做：** 多步，覆盖拖拽、改宽高、输入、键盘微调。
- **对齐：** 多选后可左/右/上/下/水平居中/垂直居中对齐，以及等间距分布。
- **缩放：** 画布可放大缩小（以鼠标为中心），缩放不改变坐标数值。

## 8. 范围
### MVP 做
导入、画布与网格、显示与选中、实时坐标、拖拽 + 吸附（可关闭）、组件间贴齐与引导线、拖边改宽高、坐标输入、方向键微调、撤销/重做、对齐/分布、导出。

### 不做
- 读取 PBIP / 解析 visual.json；写回文件（均由 AI/脚本完成）
- 画新矩形；非 16:9 页面（开源后他人扩展）
- 渲染组件真实内容（仅占位矩形+标签）

## 9. 约束
单个 HTML 文件，纯前端，数据不离开本机。坐标为整数，原点为页面左上角。
