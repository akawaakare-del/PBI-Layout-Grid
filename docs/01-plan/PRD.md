# PBI Layout Grid — 产品需求文档（草稿 v0.3）

## 1. 一句话
单文件网页工具：**输入**一份"组件+坐标"列表，用户在 16:9 画布上拖拽调整位置，**输出**修改后的列表。核心是拖拽体验要明显好于在 Power BI 里调。

## 2. 背景与痛点
- 在 Power BI 里精确摆放视觉：逐个点选、手输坐标、看不到整页全貌、没有好用的吸附。
- 作者对布局要求严格，调一次布局需 **2–3 小时**（基线）。
- 开发阶段为 PBIP（新格式 PBIR），AI 直接修改 JSON，缺的是"人直观确定目标位置并交给 AI"的一环。

## 3. 用户
内部 BI 团队约 2 人；后续可能开源。

## 4. 成功标准
- 基线：一次布局 2–3 小时。目标：**≤ 30 分钟**。
- 定性：拖动手感比 Power BI 好；自动吸附让对齐不费力；改坐标步骤比 Power BI 更少。

## 5. 职责边界
| 环节 | 谁负责 |
|------|--------|
| 从 PBIP 的 visual.json 提取组件坐标列表 | **不在本工具内**（由 AI/脚本完成） |
| 导入列表、拖拽调整、导出新列表 | **本工具** |
| 把新列表写回 visual.json | **不在本工具内**（由 AI 完成） |

## 6. 输入 / 输出格式
**暂留空**，由作者后续整理。原则：输入与输出**结构保持一致**，且**尽可能简单**（回灌 AI 无需转换）。

## 7. 版面与交互设计原则
**版面：** 左右两栏。
- **左：工作台** — 上部：选中组件的 X / Y / 宽 / 高输入框（常驻）与组件列表；下部：**已保存的坐标点列表**。
- **右：工作区** — 16:9 画布。

**组件表示：** 每个组件是画布上的**矩形**，标注类型/标题/id；不渲染真实内容。

**吸附：**
- 背景网格 10px；拖动默认吸附到 10px 网格。
- 拖到其他组件的边/中心 10px 内时，**自动吸附对齐**该组件并出引导线、显示间距。
- **吸附开关为界面按钮**（不用 Alt 之类的按键），关闭后可到 1px 精度。
- 按住 **Shift** 拖动：锁定为水平或垂直直线移动。

**输入坐标：** 选中即见输入框，Tab 切换、Enter 应用，框内上下键加减。比 Power BI 的"选组件→开面板→展开→输入"步骤更少。

**键盘：** 方向键 1px 微调（Shift 10px）。

**保存坐标点：** 单击画布保存该点坐标，显示在工作台下部，可命名/删除/复制。

**撤销/重做：** 覆盖拖拽、改宽高、输入、键盘微调。

**缩放：** 画布可缩放（以鼠标为中心），不改变坐标数值。

## 8. 范围
### MVP 做
导入、画布与网格、显示与选中、实时坐标、拖拽 + 吸附（按钮可关闭）、Shift 直线移动、吸附对齐其他组件并出引导线、拖边改宽高、坐标输入、方向键微调、保存坐标点、撤销/重做、导出。

### 不做
- 读取 PBIP / 解析 visual.json；写回文件（均由 AI/脚本完成）
- 画新矩形；非 16:9 页面（开源后他人扩展）
- 多选后的对齐/分布按钮（"对齐"指拖拽时吸附，已满足）
- 渲染组件真实内容（仅占位矩形+标签）

## 9. 约束
单个 HTML 文件，纯前端，数据不离开本机。坐标为整数，原点为页面左上角。
