# PBI Layout Grid — 产品需求文档（草稿 v0.1）

## 1. 一句话
一个单文件网页工具：导入 Power BI PBIP 报表，在 16:9 画布上看到每个视觉对象的位置，拖拽调整并读出精确坐标，把结果交给 AI 去改 JSON。

## 2. 背景与痛点
- 开发报表时要精确调整视觉对象位置：只能逐个点选，再打开位置面板手输数值，且看不到整页的坐标全貌。
- Power BI 自带网格/吸附/对齐不够精确，且无法产出可交给 AI 的结构化信息。
- 目前开发阶段报表为 PBIP，AI 直接修改 JSON，缺的是"让人直观确定目标位置，并告诉 AI"的一环。

## 3. 用户
- 内部 BI 团队，约 2 人；后续可能开源。

## 4. 成功标准
- 修一次报表布局的时间显著下降（基线待测：请记录一次当前耗时）。
- 人只需在网页里拖到位，AI 不需再追问"改哪个、改到哪"。

## 5. 核心流程
1. 导入 PBIP 报表（读取各页面及视觉对象的 position）。
2. 在 16:9 画布（1280×720，10px 网格，可缩放）上查看现有视觉。
3. 拖拽视觉到目标位置（吸附 10px，整数）；悬停显示坐标；单击保存坐标。
4. 一键复制"变更清单"（含视觉 id、类型、旧位置→新位置、已保存的点）。
5. 把清单交给 AI，AI 修改对应 visual.json。

## 6. 范围
### MVP 做
- 导入 PBIP、多页切换、显示现有视觉
- 1280×720 画布、10px 网格、缩放/平移
- 悬停坐标、单击保存坐标
- 拖拽移动并吸附 10px
- 复制 AI 可读的变更清单

### 不做
- 画新矩形（已由"读取现有视觉"取代）
- 非 16:9 / 自定义页面尺寸（开源后由他人扩展）
- 直接修改报表文件（由 AI 改 JSON）；是否直接写回见待定问题
- 渲染视觉的真实内容（只画占位矩形+标签）

## 7. 约束
- 形态：单个 HTML 文件，纯前端，数据不离开本机。
- 坐标均为整数像素，原点为页面左上角，格式对应 Power BI 位置面板的 x / y / 宽 / 高。
