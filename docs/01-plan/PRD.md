# PBI Layout Grid — 产品需求文档（草稿 v0.2）

## 1. 一句话
单文件网页工具：**输入**一份"组件+坐标"列表，用户在 16:9 画布上拖拽调整位置，**输出**修改后的列表。核心是拖拽体验要明显好于在 Power BI 里调。

## 2. 背景与痛点
- 在 Power BI 里精确摆放视觉：逐个点选、手输坐标、看不到整页全貌、没有好用的吸附。
- 作者对布局要求严格，调一次布局需 **2–3 小时**（基线）。
- 开发阶段为 PBIP（新格式 PBIR），AI 直接修改 JSON，缺的是"人直观确定目标位置并交给 AI"的一环。

## 3. 用户
内部 BI 团队约 2 人；后续可能开源。

## 4. 成功标准
- 基线：一次布局 2–3 小时。目标：待定（建议 ≤ 30 分钟）。
- 定性：拖动手感比 Power BI 好；5px 自动吸附让对齐不费力。

## 5. 职责边界
| 环节 | 谁负责 |
|------|--------|
| 从 PBIP 的 visual.json 提取组件坐标列表 | **不在本工具内**（由 AI/脚本完成） |
| 导入列表、拖拽调整、导出新列表 | **本工具** |
| 把新列表写回 visual.json | **不在本工具内**（由 AI 完成） |

## 6. 输入 / 输出格式（拟定，待确认）
输入：
```json
{
  "page": { "name": "Overview", "width": 1280, "height": 720 },
  "visuals": [
    { "id": "a1b2c3", "type": "barChart", "title": "销售额", "x": 40, "y": 80, "width": 300, "height": 120, "z": 1000 }
  ]
}
```
输出：同结构，坐标为修改后的值，并为有变化的组件加 `"changed": true`，保证可回灌、可直接交给 AI。坐标均为整数，原点为页面左上角。

## 7. 范围
### MVP 做
- 导入列表、1280×720 画布、10px 背景网格、缩放/平移
- 拖拽移动，**5px 自动吸附**（含对其他组件边缘/中心的吸附与引导线，待确认）
- 悬停/拖拽时实时显示坐标
- 撤销/重做/重置
- 导出修改后的列表

### 不做
- 读取 PBIP / 解析 visual.json；写回文件
- 画新矩形；非 16:9 页面（开源后他人扩展）
- 渲染组件真实内容（仅占位矩形+标签）

## 8. 约束
单个 HTML 文件，纯前端，数据不离开本机。
