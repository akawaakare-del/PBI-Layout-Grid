# Sprint 1 开发 Prompt（交给 AI 编码用）

> 使用方法：把本文整段发给 AI，并附上 `docs/01-plan/PRD.md`、`docs/01-plan/user-stories/stories.md`、`docs/01-plan/io-samples/` 下的样例 CSV。产物放 `src/main/index.html`。

```
你是资深前端工程师。请为 Power BI 报表开发者做一个【单文件网页工具】PBI-Layout-Grid 的第一迭代（Sprint 1）。

## 一、工具是什么
开发者在 Power BI 里手工摆放视觉组件（卡片/切片器/图表…）很慢，要一个个点开、输坐标。本工具接收"已提取好的组件坐标 CSV"，在 16:9 画布上把每个组件显示成矩形，用户拖拽调整，然后导出"修改后的 CSV"。
- 工具【不】读写 PBIP/visual.json，不渲染组件真实内容，不能新建矩形。只做：导入 CSV → 拖拽调整 → 导出 CSV。
- 核心目标：调位置的体验要明显好过在 Power BI 里调（目标：布局时间从 2~3 小时降到 30 分钟内）。

## 二、硬性约束
- 单个 index.html，纯前端，原生 JS/CSS，无需构建、不依赖 CDN（离线可用）、不上传任何数据。可用 ES2020+，目标浏览器：最新版 Edge/Chrome。
- 画布逻辑尺寸固定 1280×720，原点左上角，坐标一律整数。
- 代码结构清晰：把"状态/数据模型""命令（撤销重做）""渲染""交互"分层，注释写关键约束。Sprint 2 要在此基础上加：组件吸附+引导线、拖边改宽高、坐标输入框、方向键微调、Shift 直线移动、右键保存坐标点——请预留扩展点，但本迭代不要实现它们。

## 三、输入 / 输出格式（输入输出完全相同）
CSV，UTF-8（可能带 BOM，需兼容），列固定：
Page,Id,Type,X,Y,Width,Height
- 一行一个组件；多页报表放同一个 CSV，用 Page 区分；网页一次显示一页，需有页面切换。
- 样例见 docs/01-plan/io-samples/*.csv（Page 值可能含前导空格，如 "  嘉聯"，必须原样保留，不得 trim；同名 Page 视为同一页）。
- 解析要健壮：带引号字段、字段内逗号、CRLF/LF、BOM、空行。
- X/Y/Width/Height 应为整数；若遇到小数则四舍五入并在导入提示里提醒；非数字、负数、超出 1280×720 的行：明确提示"第几行 / 哪个 Id / 哪个字段"，错误行不导入但不阻断其他行。
- 导出：列、列顺序、行顺序、Page 原文与输入完全一致，只有 X/Y/Width/Height 的值可能不同；UTF-8 带 BOM；文件名 <原文件名>-modified.csv；导出全部页面（含未修改页）。

## 四、Sprint 1 要实现的功能（本迭代范围，逐条验收）
1. **导入（US-01）**：按钮选择文件 + 拖文件到页面均可；解析成功后显示页面切换、组件数量；格式错误给出清晰提示。
2. **画布（US-02）**：1280×720 逻辑画布，背景 10px 网格（每 50/100px 可略加深便于读数）；滚轮以鼠标为中心缩放（建议 25%~400%）；在空白处按住拖动（或空格+拖动/中键）平移；缩放/平移不改变任何坐标；提供"适应窗口"按钮；显示当前缩放比例。
3. **显示与选中（US-03、US-14）**：左右两栏布局——左【工作台】：上部为组件列表（显示 Type + Id 前 6 位，可点选，与画布选中联动、滚动到选中项），下部预留"已保存坐标点"区域（本迭代仅放占位标题）；右【工作区】：画布。每个组件是矩形，标注 Type 与 Id（太小则裁剪/仅显示 Type，不溢出）；不同 Type 用有区分度的淡色；选中高亮并带 8 个手柄的外框（手柄本迭代仅展示，不可拖）；点击重叠处选中最上层，点空白取消选中。
4. **实时坐标（US-04）**：鼠标在画布上悬停时显示画布坐标（整数）；拖拽中显示 x/y/宽/高及相对原位置的位移；选中组件的 X/Y/W/H 在左上以只读文字显示（可编辑输入框是 Sprint 2）。
5. **拖拽 + 网格吸附（US-05）**：左键拖动组件移动；默认松手/移动中位置吸附到 10px 网格（移动的是组件左上角 x、y 对齐到 10 的倍数）；工具栏有两个独立开关按钮「网格吸附」「组件吸附」，默认网格吸附开；「组件吸附」按钮本迭代先放置并可切换状态，但无实际吸附逻辑（标注"S2"）；网格吸附关闭时精度为 1px；不可拖出画布（夹紧到边界内）；拖动时在原位置保留虚线轮廓；不要用 Alt 等修饰键切换吸附。
6. **撤销/重做/重置（US-06）**：命令栈式实现（每次拖拽结束为一条命令）；Ctrl+Z / Ctrl+Y(或 Ctrl+Shift+Z)；工具栏按钮；"重置"回到导入时状态（可再撤销）；跨页面共享同一条历史还是每页独立，请选一种并在代码注释说明（推荐全局一条）。
7. **导出（US-07）**：按钮导出 CSV；有改动的组件在列表和画布上有"已修改"标记，并显示改动数量；未导入时导出按钮禁用。
8. **体验细节**：矩形最小可点区域保护（极小组件也能选中）；大量组件（≥300）拖动保持流畅（用 SVG 或 Canvas 均可，请说明选型理由；建议拖动时只更新受影响元素）；中文界面，字体清晰；坐标文字不随缩放而糊或过小。

## 五、本迭代明确不做
组件吸附与引导线、拖边改宽高、X/Y/W/H 输入框、方向键微调、Shift 直线移动、右键保存坐标点、多选、对齐/分布、新建/删除矩形、读写 PBIP。

## 六、交付物与验收
- 交付：src/main/index.html（单文件）；另在 src/test/unit/ 放一个可用 Node 直接运行（无需第三方依赖）的解析/导出/撤销栈测试脚本，至少覆盖：带 BOM 的 CSV、引号与逗号字段、Page 前导空格原样保留、导入后原样导出（不改动）与输入逐字节等价（BOM/换行风格按约定统一为 CRLF 或说明）、小数取整提示、非法行提示、撤销重做一致性。为此请把纯逻辑（解析/序列化/命令栈）写成可在浏览器与 Node 复用的独立代码块。
- 验收清单（请逐条自测并在回复中列出结果）：
  1. 导入样例 CSV，68 个组件全部可见、页面切换正常；
  2. 滚轮缩放以鼠标为中心，坐标读数不变；
  3. 拖动一个组件，松手后坐标为 10 的倍数；关闭网格吸附后可得到非 10 倍数的整数；
  4. 撤销/重做/重置行为正确；
  5. 不改任何东西导出，与输入内容一致；改一个组件后导出，仅该行的坐标变化；
  6. 组件列表与画布选中联动；重叠处点击选中最上层；
  7. 控制台无报错。
- 回复时先简述架构与关键决策，再列验收结果与已知限制；不要擅自扩大范围。
```
